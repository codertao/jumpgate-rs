# Jumpgate Classic: notes and extracts

This folder holds notes and extracts about **Jumpgate Classic as it is**: the client, its protocol and
crypto, and what the classic server did, as far as the binary and our
captures show. It doesn't describe our server or agents; those are in
`../docs/` (index: ../docs/README.md). When a fact here was confirmed by
running our own code against the client, it is tagged [live], but the design
of that code lives in docs.

Working notes on this Jumpgate revival client (`Jumpgate.exe`, SHA-256 `fef6e50f...`, "2.0127" build, server
`jumpgate-tri.org`). Produced by reverse engineering + one captured session on
2026-11-10. Verify the binary hash before trusting any address.

## Security headlines
- Transport is AES (RakNet secure mode) but the key exchange is **unauthenticated**
  with a **Mersenne-Twister RNG** → active MitM is feasible on an intercepted link.
- Login **password is cleartext** inside the game layer. Capture files can contain
  it — the ones saved here are redacted/server-side-only. Since 2026-11-11 the
  shim redacts the password itself when recording, but older raw captures still
  hold it: keep them private and delete them.
- Server→client **type 0xFE** does unrestricted memory writes into the client
  (server-pushed patching, no checks). Observed use was benign (renaming medals).

## Status / open items
- Flight physics: fully located and written up in physics.md (static only, not
  yet runtime-confirmed). The client is authoritative for its own movement.
  Remote ships are dead-reckoned. Network errors under 200 u are blended into
  velocity, larger ones snap. Player ships don't really collide: they get a soft
  push only, and the elastic bounce is for gates and world objects.
- Message field layouts: solid for type bytes + early offsets, partial for deeper
  structure (marked [inferred] in message-types.md).
- Key exchange: primitives and handshake layout confirmed; exact modulus sourcing
  and AES mode not fully traced (see key-exchange.md "Still open").
- Not needed for the message-layer MitM, which works inside the crypto boundary.

> Scope: this is for understanding and intercepting one's **own** client on one's
> own machine. Don't point the tooling at the live server or other players.
